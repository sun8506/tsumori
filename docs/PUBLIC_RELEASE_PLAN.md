# Tsumori 公开发布前规划

## 1. 结论

当前版本可以继续作为个人工具或受控的小范围演示，但不建议直接部署为任何人都能注册使用的互联网服务。

公开前最大的风险不是功能数量，而是账号、数据隔离、API Key、安全和可靠性。应先完成平台基础，再增加增长型功能。

## 2. 当前能力与边界

已有能力：

- 每日打卡、学习汇总、昨日重点和历史明细
- 单词本与间隔复习
- 短句收藏
- AI 翻译和日语理解
- 分级阅读生成与朗读
- 口语识别练习
- 学习画像、AI 服务商选择、数据导入导出
- 桌面端和移动端适配

当前边界：

- 数据主要保存在浏览器 `localStorage`
- 已有本地注册登录和会话，但没有服务端认证、邮箱验证和找回密码
- 本地学习数据已按账号隔离，但仍缺少服务端权限校验
- API Key 存在浏览器中，并随请求发送给本地服务
- 没有数据库、云同步、服务端备份和跨设备恢复
- 没有限流、配额、审计、告警和运营后台
- 自动化测试和浏览器兼容性验证不足
- 已支持六种界面语言，后续仍需持续检查新增功能的翻译完整性
- 已有本地隐私同意提示，公开服务仍需正式法律文本与服务端账号注销流程

## 3. P0：开放前阻断项

以下项目完成前，不应公开注册。

### 3.1 正式账号与身份认证

- 邮箱或第三方登录
- 密码安全存储或使用成熟身份服务
- 登录会话、退出和设备管理
- 邮箱验证、密码重置
- 注销账号和删除个人数据

验收标准：不同账号无法访问、修改或推断其他账号的数据。

### 3.2 服务端数据库与数据模型

- 建立用户、学习资料、单词、短句、复习记录、文章、打卡记录表
- 所有记录必须包含 `user_id`
- 服务端执行权限校验，不能依赖前端过滤
- 为现有 localStorage 数据提供一次性迁移或导入机制
- 数据库备份、恢复演练和迁移版本管理

建议优先使用成熟关系型数据库，例如 PostgreSQL。

### 3.3 API Key 与 AI 调用安全

推荐采用平台统一管理 AI Key，用户只获得站内额度。不要把平台 Key 返回浏览器。

必须具备：

- 服务端密钥管理和环境变量配置
- 请求鉴权
- 单用户与单 IP 限流
- 每日、每月额度
- 超时、重试和熔断
- 提示词和输入长度限制
- 成本统计及异常消费告警
- 日志中禁止记录 API Key 和完整敏感输入

若保留“用户自带 Key”模式，应加密存储，并明确风险与删除方式。

### 3.4 数据安全与隐私

- 全站 HTTPS
- 输入校验、输出转义和 Content Security Policy
- CSRF、XSS、越权和接口滥用测试
- 隐私政策、用户协议和 AI 内容免责声明
- 说明数据保存位置、用途和保存期限
- 数据导出、注销及彻底删除流程
- 最小化收集语音、查询和学习画像数据

当前口语练习不应默认保存录音。未来若保存，必须单独征得同意。

### 3.5 关键功能正确性

- 修复全部乱码和中英文混用
- 统一日期、时区和每日统计口径
- 真正按用户隔离所有学习模块
- 明确“阅读完成”的判断，不能仅把文章生成当作已阅读
- 短句增加复习机制，或明确其仅是收藏夹
- 删除操作提供二次确认和短时间撤销
- 导入前校验文件结构，并避免意外覆盖数据

### 3.6 测试与发布基础

- Storage、复习算法、每日统计的单元测试
- 注册登录、加词、复习、生成阅读、导出数据的端到端测试
- 手机和桌面主流浏览器测试
- 开发、测试、生产环境隔离
- 自动构建和部署流程
- 错误监控、接口指标和健康检查
- 数据库备份与回滚方案

## 4. P1：邀请内测必需

P0 完成后，建议先做邀请制内测。

### 4.1 新手引导

- 首次登录设置母语、等级、目标和行业
- 3 分钟产品导览
- 示例单词、短句和阅读
- AI 未配置或额度不足时给出明确引导

### 4.2 学习计划

- 每日目标：新增单词、复习量、阅读时长
- 连续学习天数
- 未完成提醒
- 每周总结
- 可关闭的浏览器、邮件或应用内提醒

### 4.3 更完整的学习记录

- 日历视图和任意日期查询
- 周报、月报
- 正确率、困难词和遗忘趋势
- 阅读完成状态与阅读时长
- 口语练习次数和历史结果
- 数据筛选与搜索

### 4.4 内容管理

- 单词和短句搜索、标签、批量操作
- 重复内容检测
- 收藏、归档和恢复站
- 例句与来源信息
- 词库导入，例如 CSV

### 4.5 AI 使用体验

- 生成进度、取消和重试
- 结果反馈：有用、错误、需改进
- 内容安全过滤
- 模型故障时的降级提示
- 额度显示和成本透明
- 缓存相同请求，降低成本

### 4.6 支持与反馈

- 站内问题反馈
- 版本号和更新记录
- 常见问题页面
- 管理员查看错误、用户反馈和额度使用的后台

## 5. P2：公开版增强

这些功能有价值，但不应先于账号安全和数据可靠性。

- PWA 安装与离线查看
- 云端多设备同步
- 手机推送通知
- 自定义词库和学习课程
- JLPT 主题词库
- 更专业的口语发音评分
- 学习小组、教师或企业管理
- 分享学习报告
- 订阅与付费套餐
- 多语言界面
- 无障碍能力完善

## 6. 建议发布阶段

### 阶段 A：个人稳定版

目标：先把现有功能做稳。

- 修复乱码和统计口径
- 补齐测试
- 完善导入导出
- 完成当前用户说明

### 阶段 B：封闭内测

目标：支持 10 至 30 名受邀用户。

- 完成账号、数据库和全量用户隔离
- 平台托管 AI Key 与额度
- HTTPS、日志、监控和备份
- 收集真实使用反馈

### 阶段 C：公开测试

目标：允许申请或限量注册。

- 完成隐私政策、用户协议和注销
- 增加新手引导、学习目标、反馈渠道
- 进行安全测试和容量测试
- 建立客服与事故响应流程

### 阶段 D：正式开放

目标：可持续运营。

- 明确免费额度与付费策略
- 建立成本、留存和学习效果指标
- 完善运营后台和内容治理
- 定期备份恢复演练与安全审查

## 7. 推荐的下一轮开发顺序

1. 修复编码、语言一致性和统计定义。
2. 设计数据库 schema，并让全部记录带有 `user_id`。
3. 增加服务端 API 层，前端不再直接读写核心业务数据。
4. 接入账号认证和权限校验。
5. 将 AI Key 移到服务端，增加额度、限流和成本监控。
6. 编写迁移、单元和端到端测试。
7. 增加新手引导、学习目标和完整日历报告。
8. 完成隐私政策、安全测试、部署监控后开始邀请内测。

## 8. 内测上线验收清单

- [ ] 两个测试账号的数据完全隔离
- [ ] API Key 不出现在网页源码、浏览器存储和日志中
- [ ] 所有写接口都需要认证并校验资源所有权
- [ ] 数据可导出、可删除、可从备份恢复
- [ ] 核心学习流程有自动化测试
- [ ] 手机端主要页面可用
- [ ] 无已知乱码和阻断级错误
- [ ] 有隐私政策、用户协议和 AI 提示
- [ ] 有错误监控、成本告警和服务健康检查
- [ ] 有用户反馈入口和问题处理负责人
